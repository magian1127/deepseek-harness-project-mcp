# 行为契约（behavior）

> 本文件是 `.mcp.json` 语义、传输支持、命名规范化、信任模型与命令输出的**唯一权威位置**。
> 面向用户的概览见 [`../README.md`](../README.md)；实现规则见 [`development.md`](development.md)；
> 设计依据见 [`design.md`](design.md)；按症状诊断见 [`troubleshooting.md`](troubleshooting.md)。

## 1. 适用范围

本插件让**项目根目录**的 `.mcp.json` 决定该项目下的会话启用哪些 MCP 服务器。

- **项目根**：从会话工作区（`session.header.cwd`）向上找到的第一个含 `.git` 的目录；
  一路到文件系统根都没有 `.git` 时，用工作区目录本身。
- **项目级服务器**：由 `.mcp.json` 声明、本插件按会话挂载的服务器。它们与 profile 里的
  **全局 MCP 行**是两套东西（见 §8）。
- **作用域**：每个会话按自己的工作区独立判定。同一进程里两个会话可以各自挂载不同的项目
  服务器；反过来，同一个项目在 N 个会话下就是 **N 份连接与子进程**。
- **子代理不挂载**：`origin === 'subagent'` 的会话被跳过（子代理与父会话共享工作区，
  重复建连接与子进程没有意义）。
- **分叉会话照常挂载**：分叉会话（fork）的 header 里也有 `parentSession`，但**不带**
  `origin`，是独立会话，因此与普通会话同样参与挂载判定。判据只有 `origin` 一条。

## 2. `.mcp.json` 的读取与解析

输入采用 Claude Code 约定格式：

```json
{
  "mcpServers": {
    "<服务器名>": { ... }
  }
}
```

解析结果与后续行为：

| 文件状态 | 行为 |
| --- | --- |
| 文件不存在（含任何读取失败，例如权限不足） | **静默跳过**，不挂载、不提示 |
| 不是合法 JSON | 不挂载；注入会话提示；`/mcp-project` 显示原因 |
| 顶层不是 JSON 对象（数组、字符串、数字、`null`） | 同上 |
| `mcpServers` 缺失 | 视为空（**不报错**）；`/mcp-project` 会说明这份文件没有声明任何服务器 |
| `mcpServers` 不是对象 | 不挂载；注入会话提示；`/mcp-project` 显示原因 |
| 单条服务器条目非法 | 只跳过该条，其余照常挂载；原因在 `/mcp-project` 可见 |

诊断文本只说明"哪里不对"（路径 + 原因），**不回显文件内容**——`.mcp.json` 可能含凭据，
而 `JSON.parse` 的错误消息本身会回显原文片段。

## 3. 条目字段语义

| 输入形状 | 输出传输 | 备注 |
| --- | --- | --- |
| `{command, args?, env?}` | `stdio` | `cwd` = 会话工作区（不是项目根） |
| `{type: "stdio", command, args?, env?}` | `stdio` | 显式写法，等价 |
| `{type: "http" \| "streamable-http", url, headers?}` | `streamable-http` | `http` 是 `streamable-http` 的别名 |
| `{type: "sse", url}` | **跳过** | DSH 不支持，见 §4 |
| `{type: "ws", url}` | **跳过** | DSH 不支持 |
| `{type: "sdk"}` | **跳过** | 仅 SDK 宿主可注册 |
| `{url}` 但无 `type` | **跳过** | 无法判断传输类型；它会被误读为 stdio 并因缺 `command` 而失败 |
| `type` 不是字符串 | **跳过** | 只支持字符串字面量 |

字段级约束：

| 字段 | 约束 | 违反时 |
| --- | --- | --- |
| `command`（stdio） | 必须是非空字符串，**展开后也必须非空** | 跳过该条 |
| `args` | 必须是字符串数组；缺省为 `[]` | 跳过该条 |
| `env` | 必须是"字符串 → 字符串"的对象；缺省为 `{}` | 跳过该条 |
| `url`（HTTP） | 必须是非空字符串，**展开后也必须非空** | 跳过该条 |
| `headers` | 必须是"字符串 → 字符串"的对象；缺省为 `{}` | 跳过该条 |
| 条目本身 | 必须是 JSON 对象 | 跳过该条 |

"展开后也必须非空"是独立于字段类型检查的一道复查：`"command": "${CMD:-}"`（或 `CMD`
本身是空串）展开后得到空串，而下游 schema 只要求字符串、不校验非空——空 `command` 会
一路走到 `spawn('')` 才抛错，只落一条日志，服务器却已被列为已挂载。因此展开为空串时
按上表**跳过该条**并在 `/mcp-project` 说明。`env` / `headers` 的键与值按普通数据键处理：
即使键名是 `__proto__` 也原样保留并传给服务器，不会被丢弃（见 §6.2 的同类说明）。

`env` 是**附加**环境变量，不是替换：服务器进程继承宿主环境，再叠加这里给出的键。

### 3.1 变量展开

`command`、`args` 的每个元素、`env` 的**键与值**、`url`、`headers` 的**键与值**都支持：

| 写法 | 语义 |
| --- | --- |
| `${VAR}` | 取变量 `VAR` 的值 |
| `${VAR:-default}` | `VAR` 已定义时取其值，否则取 `default` |
| `${VAR:-}` | `VAR` 已定义时取其值，否则取空串（用于"可选但可留空"的凭据） |

判定与边界：

1. **只认自有属性**：`env` 里存在该名字（且不为 `undefined`）即算"已定义"。
   原型链成员（`toString` / `constructor` / `valueOf` 等）**不算**已定义——否则
   `.mcp.json` 里字面写 `${toString}` 就会把一段 JS 源码展开进 `command` / `url` / `env`。
2. **空串是已定义的值**：`VAR=''` 时 `${VAR:-default}` 取**空串**，**不**取 default。
   这与 bash 的 `${VAR-default}`（不带冒号）一致，与 `${VAR:-default}`（带冒号）不同。
   理由：空串通常是用户显式设置的结果，静默替换成 default 会掩盖配置意图。
3. **变量未定义且无默认值** → 跳过该服务器，诊断只报**变量名**，不报值。
   理由：带未展开的 `${VAR}` 字面量启动，几乎必然导致认证失败且错误难以理解。
4. 多处缺变量时只报**第一个**（诊断要短，多变量名没有增量信息）。
5. 变量名沿用 POSIX 形状 `[A-Za-z_][A-Za-z0-9_]*`；不匹配的 `${...}` 原样保留，不展开。
6. 展开只在内存中进行，不落盘、不入日志、不入会话记录。

## 4. 传输支持矩阵

| 传输 | 支持 | 依据 |
| --- | --- | --- |
| `stdio` | ✅ | DSH `createTransport` 的 `stdio` 分支 |
| `streamable-http`（含别名 `http`） | ✅ | DSH `createTransport` 的 `streamable-http` 分支 |
| `sse` | ❌ 跳过 | DSH 的 `createTransport` 是封闭 switch，只有上面两个分支 |
| `ws` | ❌ 跳过 | 同上 |
| `sdk` | ❌ 跳过 | 仅 SDK 宿主可注册 |

MCP TypeScript SDK 2.0 确实导出 `SSEClientTransport`（已标记 deprecated），但支持它必须改
DSH 源码，超出"只加插件"的范围。实际影响很小：SSE 已被 MCP 规范废弃，主流服务器都提供
`streamable-http`。

## 5. 服务器命名与工具名映射

`serverName` 必须匹配 `/^[A-Za-z0-9_-]{1,32}$/` 且在同一会话的注册作用域内唯一。

`.mcp.json` 的键允许其他字符，因此需要规范化：

1. 已匹配该模式 → **原样使用**（既有工具名不变）。
2. 不匹配 → NFKD 规范化 → 非 `[A-Za-z0-9_-]` 的字符替换为 `_` → 去掉首尾 `_` →
   截断 20 字符 → 若结果为空则用 `server` → 追加 `_` + **原始键名**的 sha256 前 8 位。
3. 哈希基于**原始键名**而非 slug：否则 `a b` 与 `a  b` 会得到同一结果并在同一作用域内撞名。
4. 同一文件内规范化后重名 → **先到者胜**，后者跳过并在 `/mcp-project` 说明。

例：键 `my server!` → 规范化后形如 `my_server_<8位哈希>`。

**工具名映射**：服务器的工具以 `mcp__<serverName>__<toolName>` 出现。重命名过的服务器用
**规范名**，因此 `/mcp-project` 会同时显示原名与规范名——照着规范名去批准或去工具列表里
查找。

规范化是稳定的：同一键名始终得到同一结果，重启与重开会话不会改变工具名。

## 6. 信任模型

### 6.1 存储

`${DSH_HOME:-~/.dsh}/project-mcp-trust.json`，权限 `0600`，原子写 + 文件锁
（`@deepseek-ai/dsh-atomic-write` 可用时；不可用时降级为"同目录临时文件 + rename"，
仍是原子替换，只失去跨进程串行化）。

```json
{
  "version": 1,
  "projects": {
    "<项目根路径>": {
      "approvedAt": "2026-10-06T12:00:00.000Z",
      "fingerprint": "sha256:<hex>",
      "servers": ["github", "memory"]
    }
  }
}
```

`servers` 记录批准时该指纹下**实际存在且被批准**的服务器名。挂载时取批准列表与当前文件
列表的交集——文件里新增的服务器不会因为旧批准而生效。

### 6.2 指纹语义

指纹是 `sha256(规范化 JSON)`，形式 `sha256:<hex>`。

**规范化**：解析后按 key 字典序递归序列化，数组保序，剔除空白与键序这类纯格式差异。

因此：

| 变更 | 是否改变指纹 |
| --- | --- |
| 调整缩进、换行、键的顺序 | **不改变**（不需要重新批准） |
| 改任何值、增删条目、改服务器名 | **改变**（必须重新批准） |
| `git pull` 拉入新服务器 | **改变**（必须重新批准） |
| 加入 `__proto__` 键的条目 | **改变**（该键被当作普通数据键保留，不会被丢弃） |
| `env` / `headers` 里的 `__proto__` 键 | 同上：作为普通数据键保留并传给服务器，不会静默消失 |
| 嵌套深度超过 64 层 | 降级为对**原文**取指纹（仍对内容敏感，只是格式差异也会要求重新批准） |

最后两条是刻意的保守降级：偏保守的方向只会多要求一次批准，不会让内容变更逃过指纹。

### 6.3 失败关闭

信任文件缺失、JSON 损坏、版本号不认识、任一项目条目结构不符 → 一律视为**全部未信任**，
不阻止 DSH 启动，不抛异常。本插件运行在会话创建路径上，抛异常会中断会话。

### 6.4 仓库无法自我批准

信任存储只存在于 `${DSH_HOME:-~/.dsh}`，项目内**没有任何可写入的批准通道**——`.mcp.json`
是只读的，项目里也不存在第二个被本插件读取的批准文件。克隆一个陌生仓库并打开它，不会
执行其中的任何命令。

### 6.5 为什么批准必须走命令

会话创建时没有 open turn，而宿主审批服务只在 turn 内可用。因此**无法**在会话创建时弹窗
确认，只能"不挂载 + 告知"，批准动作发生在 turn 内（`/mcp-project trust`）。

## 7. 命令

命令名 `mcp-project`；子动作从输入解析，动词大小写不敏感，**服务器名保持原样**
（`serverName` 的合法字符集区分大小写，lowercase 会让 `GitHub` 找不到）。

命令在插件 `apply` 时**全局注册一次**，通过 invocation 上的当前会话定位项目；因此它对
此后新建的会话同样可用，且不随会话销毁而注销。

| 输入 | 行为 |
| --- | --- |
| `/mcp-project` | 列出项目路径、状态、已挂载、未批准、已跳过（含原因）、规范化重命名 |
| `/mcp-project trust` | 批准整个文件（记当前指纹）并**立即把服务器挂进当前会话**（见 §10.1） |
| `/mcp-project trust <名称>…` | 只批准指定服务器；同一指纹下已有的批准**保留** |
| `/mcp-project untrust` | 撤销该项目的批准记录，并卸载本会话已挂载的项目服务器 |
| 其他子命令 | 报错并给出用法 |

行为细节：

- **必须带名称时才校验名称**：带参数批准时，名称必须是当前**可挂载**的规范名（照
  `/mcp-project` 或会话提示里列出的抄）。写错会报错且**不写**信任存储——写进去的条目
  永远不会命中查询，批准会静默失效。
- **增量批准不挤掉已有批准**：先 `trust a` 再 `trust b` 保留 `a`；但只保留**当前指纹**
  命中的名字，文件改动后的陈旧记录不会被带过来。
- **幂等**：重复批准同一个服务器不会重复挂载（同名已挂载则跳过）。
- **批准后立即挂载**：挂进当前 agent 作用域，无需重开会话；会话提示段同时被刷新（见
  §10.1）。
- **没有可批准项时拒绝**：文件里没有可挂载服务器（一条都没声明，或全部被跳过）时，
  `trust` 报错并指向 `/mcp-project`，不会写出一条无意义的批准。
- **无 agent 时拒绝**：命令由某个会话的 UI 派发；没有会话就无法定位项目、也无处挂载。
- **撤销总是清理**：即使该项目本来就没有批准记录，`untrust` 也会卸载本会话已挂载的项目
  服务器。

### 7.1 列表输出的字段

| 行 | 何时出现 |
| --- | --- |
| `项目：<路径>` | 总是；无法定位项目根时说明 |
| `状态：…` | 总是。取值：`项目级 MCP 未启用：<原因>` / `尚未批准，本会话未挂载任何项目级 MCP` / `已批准` / `已批准，但这份文件没有可挂载的服务器` |
| `已挂载（模型可见的工具名为 mcp__<名称>__*）：` | 本会话**真实挂载**的服务器非空时 |
| `已批准但本会话未挂载（挂载只发生在会话创建时或本会话执行 trust 时）：` | 有已批准、但本会话未挂载的服务器时 |
| `未批准（用 /mcp-project trust <名称>… 只批准指定项）：` | 有可挂载但未批准项时 |
| `已跳过：` + 逐条 `- <名称>：<原因>` | 有被跳过项时 |
| `规范化重命名：` + 逐条 `- <原名> → <规范名>` | 有重命名时 |
| `（.mcp.json 里没有声明任何服务器。）` | 文件里一条都没声明时 |

"已挂载"一列取自**本会话的真实挂载记账**（插件侧按 agent 键控的 `serverName` 集合），
而不是计划：计划回答"按当前信任状态应当挂什么"，本命令回答"现在什么是活的"。两者可以
合法地不一致，因此列表分别呈现、互不代言：

- **计划要挂但本会话没挂**：最常见的是**别的会话**批准之后本会话再执行 `/mcp-project`。
  信任是全局的，所以本会话的计划同样是 `mount`，但本会话的 `agent/created` 早在批准之前
  就触发过，一个服务器都没挂上。这些项列在"已批准但本会话未挂载"下。
- **本会话挂了但计划已不含它**：挂载之后 `.mcp.json` 被改动或删除（本插件不监听文件
  变化），计划退回 `untrusted` / `skip`，而先前挂上的服务器仍在。这些项仍列在"已挂载"下。

状态行（`状态：…`）与"已挂载"是**两个独立口径**：前者描述计划，后者描述实际挂载。

**未批准项不会因为未批准而从列表消失**：即使当前状态是"尚未批准"，列表也会列出全部
可挂载服务器以及全部跳过原因。用户最需要诊断信息的时刻恰恰是批准**之前**。

## 8. 与全局 MCP 行的关系

**全局行**指 profile 补丁（bundle patch、profile 自己的 `cordis.patch.yml`、home 级
`cordis.patch.yml`、`--patch` 覆盖层）里声明的 `mcp-client` 行。它们由 DSH 在进程启动时
挂载，不受本插件管辖。

### 8.1 撞名检测口径

本插件在**每次会话创建时**按需遍历 Loader 树，收集所有 `mcp-client` 行的 `serverName`：

- **模块名精确匹配** `@deepseek-ai/dsh-mcp-client`。行名写成子路径（如
  `@deepseek-ai/dsh-mcp-client/something`）或相对路径时**漏检**——那种写法不是 DSH 声明
  MCP 行的常规形式，但若你确实这样写，撞名保护不会生效。
- 只看 `config.serverName` 是否为**非空字符串**；缺失或非字符串的行被忽略。
- 遍历 Loader **本体**（`entries()` 在 Loader 上，不在 `loader.root` 上），并下降嵌套子树。
- 任何一步失败（形状不符、`entries()` 抛错）都降级为**空集**而非半份名单：残缺名单会被
  当成完整名单，让部分项目服务器静默遮蔽全局服务器。空集是"无法判定"的表达。
- `ctx.get('loader')` 取不到 Loader 时（未挂载 Loader 的宿主）名单同样是空集，但这种情况
  会**额外记一条警告日志**——静默的空集会伪装成"没有任何全局行"。
- **不缓存**：Loader 没有覆盖"已有条目改配置"的事件，缓存会在 HMR 改配置后失效。

### 8.2 处理：跳过项目侧

`.mcp.json` 里的服务器若与全局名单撞名 → **不挂载**，`/mcp-project` 报告"与全局 MCP 行
同名，已被全局配置提供，跳过"。

为什么不警告后仍挂载：agent 作用域的同名服务器会**静默遮蔽**全局的，且会额外 spawn 一个
子进程。跳过比遮蔽更符合"全局有的本地就不要启动了"。

### 8.3 已知局限 被禁用的全局行仍占名

检测只看行的模块名与 `serverName`，**不看该行是否被禁用**。后果：

- 一条 `disabled: true` 的全局行仍会被计入全局名单；
- 同名的项目服务器因此被当作"已被全局配置提供"跳过；
- 而全局侧实际不连接 → **两边都不挂载**。

这是当前实现的已知局限。绕过方式：给项目服务器换一个不与禁用行同名的键，或启用/删除
那条全局行。

**为什么不修**：读条目的 `disabled` 属性会触发 `!!js` 表达式求值（`new Function` + `eval`），
在会话创建路径上执行用户配置的 JS，与本模块"只读、不求值"的姿态冲突。安全的修法是只判
`entry.options.disabled === true` 字面量，尚未实施。

### 8.4 能力边界

插件能检测到全局行并警告，但**无法阻止它们连接**——它们挂载得比任何会话创建都早得多。
profile 里仍有 MCP 行时，它们在 DSH 启动时就会连接并 spawn 子进程，与本插件无关。

## 9 会话提示只用于需要你行动的情形

提示文本注入会话的系统提示，会**占用模型上下文**，因此只在用户需要做一个决定或修一个
文件时注入：

| 计划状态 | 会话提示 |
| --- | --- |
| 文件不存在（`skip`，静默） | 无 |
| 会话没有工作区（`skip`） | 无 |
| 子代理会话（`origin === 'subagent'`，`skip`） | 无 |
| 服务器全部被跳过（`skip`） | 无 |
| 文件无法解析（`invalid`） | **有**：项目路径 + 原因 + "本会话未启用任何项目级 MCP" |
| 有可挂载项但未批准（`untrusted`） | **有**：项目路径 + 待批准服务器名 + 批准指引 |
| 已批准（`mount`，含 `configs` 为空） | 无 |

诊断信息（每条服务器的跳过原因、规范化重命名、`mcpServers` 缺失、"文件里没有可用服务器"）
由 `/mcp-project` 承载，用户主动查询时看到，不打扰会话。

提示文本不含任何 `.mcp.json` 内容或展开后的环境变量值；不含字面 `{{`（严格插值会在渲染期
抛错）。提示段在会话创建时注册一次，此后**随 `/mcp-project trust` / `untrust` 刷新**：
刷新走"先撤下、再按新计划重注入或留空"，文本与会话创建时同源（见 §10.1）。

## 10. 挂载语义

- **挂载点是会话的 agent 作用域**，不是宿主：项目级 MCP 必须按会话生效，挂到宿主上会让
  第一个会话的项目服务器泄漏给所有会话。
- **不等待连接**：`ctx.plugin(...)` 后立即返回，会话秒开。代价是**首条消息可能赶不上工具
  注册**——模型当轮看不到这些工具，下一轮即可见（工具注册会触发 `tools/change`）。
- **启动失败不影响会话**：挂载时设 `failOnStartupError: false`，坏服务器只记日志。
  这与 ACP 的 `failOnStartupError: true` 相反——ACP 要工具必定就位，本插件要会话必定成功。
- **每会话独立连接**：N 个会话 = N 份连接与子进程。全局行只有一份（进程级），这是本插件
  只接管项目级服务器的原因之一。
- **可逆**：挂载与提示段都随会话销毁、插件卸载（含 HMR 重载）回收，两条路径各自独立且
  可任意顺序重复执行。
- **批准后立即挂载**：`trust` 把服务器挂进当前 agent 作用域，无需重开会话；提示段也按
  新计划刷新（见 §10.1）。
- **执行不受 agent 沙箱约束**：MCP 服务器是项目提供的代码，批准后以子进程形式运行；
  这与 profile 里的全局行同性质。

### 10.1 批准后当前会话的状态

| 面 | 批准后的行为 |
| --- | --- |
| 项目服务器挂载 | **立即生效**：`trust` 挂进当前 agent 作用域，无需重开会话 |
| `/mcp-project` 列表 | **立即反映**：列表每次执行都重新检视项目并重算批准状态；"已挂载"一列读的是**本会话真实挂载记账**，不是计划 |
| 会话提示段 | **立即刷新**：`trust` 落盘并挂载之后，按新计划重算提示段——批准后计划是 `mount`，提示为空，旧段被撤下 |

批准后提示段的刷新是"先撤下、再按新计划重注入或留空"，文本与会话创建时**同源**
（同一个 `renderNotice`），因此两条路径不会分叉。撤销同理：`untrust` 之后按撤销后的计划
重算，文件仍在时会换成新的"尚未批准"提示，文件已不可用（计划为静默 `skip`）时撤下。

后果：**提示段始终与当前计划一致**，模型不会再在挂载成功之后读到"本会话未启用任何项目级
MCP"。批准前注入的旧提示不会残留。

需要留意的边界（与提示段无关）：**别的会话**批准后，本会话的计划同样变成"已批准"，但
服务器不会自动挂进本会话——挂载只发生在会话创建时或本会话自己执行 `trust` 时。
`/mcp-project` 会把这种情况列在"已批准但本会话未挂载"下（见 §7.1），运行
`/mcp-project trust` 即挂上。

## 11. 失败模式速查

| 症状 | 行为 | 去哪里看 |
| --- | --- | --- |
| 没有 `.mcp.json` | 静默跳过 | — |
| `.mcp.json` 解析失败 | 不挂载 + 会话提示 | 会话提示、`/mcp-project` |
| `mcpServers` 缺失或为空对象 | 不挂载，**不提示** | `/mcp-project` |
| 单条服务器配置非法 | 只跳过该条 | `/mcp-project` 的"已跳过" |
| 传输不支持（`sse` / `ws` / `sdk`） | 跳过该条 | `/mcp-project` 的"已跳过" |
| 有 `url` 无 `type` | 跳过该条 | `/mcp-project` 的"已跳过" |
| 变量未定义且无默认值 | 跳过该条，只报变量名 | `/mcp-project` 的"已跳过" |
| `command` / `url` 展开后为空串 | 跳过该条（否则空 `command` 会到 `spawn('')` 才失败，却被列为已挂载） | `/mcp-project` 的"已跳过" |
| 配置不满足 `mcp-client` 的 schema（如上游新增必填字段） | **挂载前拦下**该条，不交给 `ctx.plugin()`；记一条只含服务器名与出错字段的日志，绝不回显配置内容 | DSH 日志 |
| 规范化后重名 | 先到者胜，后者跳过 | `/mcp-project` 的"已跳过"与"规范化重命名" |
| 与全局行撞名 | 跳过项目侧 | `/mcp-project` 的"已跳过" |
| 指纹不匹配（文件被改） | 不挂载 + 会话提示 | 会话提示、`/mcp-project` |
| 信任文件损坏 / 版本不认识 | 全部未信任，不阻止启动 | `/mcp-project`（全部显示未批准） |
| MCP 连接失败 | 只记日志，不影响会话 | DSH 日志 |
| 拿不到 `mcp-client` 模块 | 不挂载（安全侧），记错误日志；`/mcp-project` 仍可用 | DSH 日志 |
| profile 里仍有 MCP 行 | 不受管辖，启动时即连接 | — |

## 12. 数据边界

| 数据 | 位置 |
| --- | --- |
| 信任记录（版本、项目根、批准时间、指纹、已批准服务器名） | `${DSH_HOME:-~/.dsh}/project-mcp-trust.json`，权限 `0600` |
| `.mcp.json` | 项目根目录，**只读**，本插件不写入 |

不落盘、不入日志、不入会话记录、不入错误消息：`.mcp.json` 的内容、展开后的环境变量值。
诊断只含服务器名、变量名与自造的原因文本。

## 13. 非目标

明确不做（YAGNI）：

- 不支持 `ws` / `sse` 传输。
- 不做 OAuth 流程。
- 不做 GUI 面板，只做斜杠命令。
- 不接管 profile 里的全局 MCP 行。
- 不做按服务器的细粒度开关（只做整文件批准与按名批准两档）。
- 不做 `.mcp.json` 的写入或管理。
