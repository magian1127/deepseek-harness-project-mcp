# deepseek-harness-project-mcp

[中文](README.md) · [English](README.en.md)

**让项目根目录的 `.mcp.json` 决定该项目下的会话启用哪些 MCP 服务器**，且未启用的服务器
**完全不建立连接、不启动子进程**。

DSH 的 MCP 配置原本只有 profile（进程）作用域：写进 profile 补丁的服务器在 DSH 启动时
就连接、就 spawn 子进程，那时还没有任何会话。本插件把"项目专属"的那部分搬到项目里——
配置随仓库走，是否启用由你按项目批准。

## 功能

| 能力 | 说明 |
| --- | --- |
| 项目级配置 | 项目根目录的 `.mcp.json`（Claude Code 约定格式）声明该项目专属的 MCP 服务器 |
| 不批准就不连 | 未批准的服务器不 spawn 进程、不发网络连接；克隆陌生仓库并打开它不会执行其中任何命令 |
| 配置哈希绑定 | 批准绑定到**每台服务器的当前配置**，`git pull` 改动哪台就只有那台需要重新批准 |
| 仓库无法自我批准 | 批准记录只存在于 `${DSH_HOME:-~/.dsh}`，项目内没有可写入的批准通道 |
| 控制台批准 | 输入区按钮 + 弹层：点 [启动] 即授权并**立即挂进当前会话**，无需重开会话 |
| 两种传输 | `stdio` 与 `streamable-http`（`http` 是别名） |
| HTTP 服务按需拉起 | HTTP 条目可用 `serve` 声明"服务没在跑时怎么启动"；健康检查失败时插件把它拉起来，等就绪再连接 |
| 变量展开 | `command` / `args` / `env` / `url` / `headers` / `serve.*` 支持 `${VAR}` 与 `${VAR:-default}` |
| 全局撞名保护 | 与 profile 全局 MCP 行同名的项目服务器不重复挂载 |
| 子代理不重复挂载 | 子代理会话（`origin === 'subagent'`）与父会话共享工作区，不重复建连接与子进程；分叉会话是独立会话，照常挂载 |
| 工具调试 Tab | 会话视图里的「工具调试」页：浏览宿主全局工具面、按表单或原始 JSON 手动调用、查看结果与历史、只看不写地浏览当前会话可见的技能、只读查看提示词段。与项目级 MCP 无关，只是搭本插件的 Host 半边 |
| 不打扰 | 没有 `.mcp.json` 时完全静默；**任何情况下都不往系统提示词写内容**，需要行动时只在按钮上给徽标 |

## 环境要求

- **DeepSeek Harness `>=0.2.0-rc.2 <0.3.0-0`**（`package.json` 的 `engines.dsh`，由宿主在安装与 profile 启动时强制校验；0.1.x 及更早会被判不兼容并拒绝加载）
- 实测基线 DSH 0.2.1-rc.2（`@deepseek-ai/dsh-mcp-client` 与 `@deepseek-ai/dsh-atomic-write` 均为 `0.2.1-rc.2`）
- Node.js `^22.19.0 || >=24.0.0`
- 本插件有 Host 半边与一个极小的 Client 半边（输入区按钮 + 弹层、工具调试 Tab），没有 Web 配置表单，也不注册模型工具

## 安装

```powershell
dsh plugin --profile web add "link:<本仓库路径>"
```

把 `<本仓库路径>` 换成本插件源码目录。安装前先构建一次：

```powershell
npm install
npm run build
```

`--profile web` 是 Web GUI 使用的 profile；按实际使用的 profile 替换（例如桌面版为
`desktop`）。`link:` 指向本仓库后，改动源码只需重新 `npm run build`。

安装完成后，该 profile 的 bundle 列表应含 `deepseek-harness-project-mcp`，Loader 里应出现
`dsh-project-mcp` 行：

```powershell
dsh plugin --profile web list
```

本插件的 Host 半边没有配置表单，Client 半边只提供输入区按钮与弹层。新构建进入长跑进程：
在官方插件页**删除 → 安装**即可（免重启，已实测）；Client 半边由宿主自动热更新，无需刷新
页面。只有 Client 半边的**首次**供应需要重启一次 DSH（宿主的模块表对"非 client 包"有进程级
负缓存）。

## `.mcp.json` 格式

放在**项目根目录**（从会话工作区向上找到的第一个含 `.git` 的目录；一路到根都没有
`.git` 时用工作区目录本身）：

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" }
    },
    "docs": {
      "type": "http",
      "url": "https://example.com/mcp",
      "headers": { "Authorization": "Bearer ${DOCS_TOKEN:-}" }
    }
  }
}
```

| 字段 | 语义 |
| --- | --- |
| 键（`github` / `docs`） | 服务器名。合法字符为 `[A-Za-z0-9_-]`，长度 1–32；不合法会被规范化并重命名 |
| `command` + `args` + `env` | stdio 服务器。`env` 是附加环境变量，`cwd` 为会话工作区 |
| `type: "http"` 或 `"streamable-http"` + `url` + `headers` | HTTP 服务器 |
| `serve`（HTTP 条目可选） | 服务没在跑时怎么启动它，见下 |
| `type: "sse"` / `"ws"` / `"sdk"` | **不支持**，跳过并给出原因（DSH 的传输工厂只有 stdio 与 streamable-http 两个分支） |
| 只有 `url` 没有 `type` | **跳过**，并提示无法判断传输类型 |

服务器的工具会以 `mcp__<服务器名>__<工具名>` 的形式出现；被规范化重命名过的服务器，
工具名用的是规范名。完整语义、跳过原因与边界见 [行为契约](docs/behavior.md)。

### HTTP 服务按需拉起（`serve`）

HTTP 模式下 DSH **不启动任何子进程**——它只向 `url` 发请求，服务必须已经在跑。若服务没在
跑，DSH 连不上、工具不可用。`serve` 让插件在这种情况下**把服务拉起来**，等它就绪再连接：

```json
{
  "mcpServers": {
    "mudblazor": {
      "type": "http",
      "url": "http://127.0.0.1:19701/mcp",
      "serve": {
        "command": "dotnet",
        "args": ["<MudBlazor.Mcp.dll 的路径>", "--version", "9.10.0"],
        "env": { "ASPNETCORE_URLS": "http://127.0.0.1:19701" },
        "health": "http://127.0.0.1:19701/health/ready",
        "readyTimeoutMs": 120000
      }
    }
  }
}
```

| 字段 | 必填 | 语义 |
| --- | --- | --- |
| `command` | ✅ | 可执行文件（或绝对路径）。与 stdio 的 `command` 同语义，**不经 shell 解释** |
| `args` | ❌ | 参数数组，默认 `[]` |
| `env` | ❌ | **追加**环境变量（宿主环境之上叠加） |
| `health` | ❌ | 就绪检查 URL（只允许 `http://` / `https://`）。省略时用 `url` 的 origin + `/health/ready` |
| `readyTimeoutMs` | ❌ | 等待就绪的上限（毫秒），默认 `120000` |

行为要点：

- **服务已在跑就完全不碰它**：先做一次健康检查（2 秒超时），成功就直接连接，零额外动作。
- **只在健康检查失败时才拉起**，然后每 250 毫秒轮询 `health`，就绪后交给 DSH 连接。
- **首条消息会等服务就绪**（最多 `readyTimeoutMs`）。这是 `serve` 唯一会让用户感知到的
  代价：等待发生在会话创建路径上，因此工具在首次请求前就注册好。等待**只影响该条目**，
  同一会话里其他服务器照旧立即挂上。
- **超时后仍会连接**：记一条日志，交给 DSH 自己重试（工具会注册但暂时不可用）。
- **拉起的服务脱离 DSH 存活**：不继承管道、启动后立即丢弃引用。POSIX 上另起进程组；Windows
  上按命令分流——`serve.command` 是 PowerShell 时**不**用 `detached`（那里的 `detached` 等于
  `DETACHED_PROCESS`，PowerShell 会一行都不执行就退出），其余命令仍用它（否则服务会挂在宿主
  控制台上、随 DSH 一起消失）。插件不 kill 它、不监控它、不重启它——多个 DSH 实例（或 DSH
  重启）复用同一个服务，何时退出由服务自己决定。想结束它就手动结束该进程。
- **两个会话同时挂载同一 `url` 只拉起一次**（按 `url` 去重）。
- **`serve` 写错不影响使用**：畸形时只丢弃 `serve`、记一条日志，该服务器照常挂载。

完整语义见 [行为契约 §3.2](docs/behavior.md#32-servehttp-条目的按需拉起可选)；
"服务没被拉起"与"等很久"的排查见 [故障排查](docs/troubleshooting.md)。

## 信任批准流程

1. 在含 `.mcp.json` 的项目里新建会话。输入区（composer 工具行）出现一个插头图标按钮，
   文字随状态变化（「检测中」/「N 个未启动」/「MCP 就绪」）；没有 `.mcp.json` 时按钮完全不出现。
2. 点按钮打开弹层，逐台服务器看到状态与原因，点 **[启动]**：

| 动作 | 行为 |
| --- | --- |
| [启动] | 授权**这一台服务器的当前配置**，并立即挂进当前会话（无需重开） |
| [重试] | 挂载失败的项重新挂一次（配置未变时不重复写批准） |
| [撤销授权] | 删除该服务器的批准记录，并卸载本会话已挂的实例 |

批准不需要重开会话。改动某台服务器的配置会让它的配置哈希失配、回到"未授权"——这正是
`git pull` 拉入新服务器时的保护；而**没改的其他服务器不受牵连**。

**批准是持久的，不是每个会话都要做**：记录写在 `${DSH_HOME:-~/.dsh}/project-mcp-trust.json`，
同一项目批准一次之后，之后所有会话都会直接挂载，不再询问。只有两种情况需要再次批准：

- 该项目的**首次**使用；
- 某台服务器的配置发生了变化（例如 `git pull` 改了它）。

诊断信息（每条服务器为什么被跳过、哪个名字被规范化、"这份文件没有可用服务器"）全部在
弹层里。**本插件不往系统提示词写任何内容**——需要你行动的事都显示在按钮上。

无 Web UI 的 profile（headless / SDK）没有控制台，因此没有批准入口，只剩 Host 日志。

## 工具调试 Tab

会话视图行（与「对话」「轨迹」并排）多出一个**「工具调试」**页。它浏览的是宿主**全局**
工具面——内置工具、各插件注册的工具、以及本插件挂载的 `mcp__<名称>__*` 都在里面。它与
项目级 MCP 没有语义关系，只是需要一个已经常驻的 Host 半边，因此搭在本插件上。

| 栏位 | 用途 |
| --- | --- |
| 左 | 搜索 + 分组工具树（每个 MCP 服务器一组、`内置工具`、`其他工具`） |
| 中 | 选中工具的参数表单（或「原始 JSON」模式），[执行] / [取消] |
| 右 | 「结果」看最近一次调用（图片可直出）、「历史」是本机最近 50 次、「技能」看**当前会话可见**的技能目录（展开才加载正文）、「提示词面」只读列出当前 `systemPrompt` section |

行为要点：

- 参数表单按工具的 JSON Schema **顶层**生成（标量/布尔/枚举），对象与数组落 JSON 编辑域；
  必填项留空会就地报错，不发请求。表单**不做** schema 校验，校验交给工具自己。
- 结果优先显示工具返回的**原始内容块**，因此图片能看见，而不是被降级成占位文本。
- 工具名或参数里出现 `unsafe` 字样时**总是**弹二次确认（「本会话跳过确认」对它无效）。
- 「技能」页读的是宿主 `skills` 服务，并按**当前会话的作用域**列举——所以 agent preset
  用 `customSkillDirs` 声明的技能也会出现。它只读，且不下发技能文件的本机路径。
- 调试台**不**往系统提示词写内容、**不**注册模型工具，模型看不到它。
- 没有 `tools` 服务的部署不装配它；没有 `webServer` 的 profile（headless / SDK）也没有这个 Tab。

> 这是人工调试入口，从宿主全局视角执行工具（不带会话作用域），因此会话级的工具限制
> **不**作用于它。它只能由同源页面手动触发（peer 回环 + `Host` 白名单 + `sec-fetch-site` /
> `Origin` 同源）。

## 数据边界

| 数据 | 位置 | 内容 |
| --- | --- | --- |
| 信任记录 | `${DSH_HOME:-~/.dsh}/project-mcp-trust.json`（权限 `0600`） | 版本号、项目根路径、每台服务器的批准时间与配置哈希（`sha256:<hex>`） |

- 信任文件**不含** `.mcp.json` 的内容，也**不含**任何展开后的环境变量值。
- `.mcp.json` 只读，本插件不写入、不管理它。
- 展开后的变量值只在内存中用于启动服务器，不写日志、不写错误消息、不写会话记录、不落盘。
- 变量未定义且无默认值时，该服务器被跳过，诊断只报**变量名**，不报值。
- 插件不收集遥测，不维护上述以外的持久数据。
- **网络请求**：本插件自己只发起一种请求——对 `serve` 的 `health`（或由 `url` 推导出的
  `/health/ready`）做就绪探测，且**只允许 `http://` / `https://`**。除此之外的网络连接
  都由 DSH 自己的 MCP 客户端发起（连你批准的 `url`）。
- **进程启动**：本插件只在 `serve` 声明且健康检查失败时启动进程，且只启动 `serve.command`
  ——不经 shell 解释，因此 `&&`、管道、重定向、通配符都不生效。未批准时既不 spawn 也不连。
- **工具调试台的数据**：调用历史只存在你浏览器的 `localStorage`（键
  `dsh-project-mcp-tool-debug-history`，上限 50 条），不上报、不落盘到 host。执行工具产生的
  结果只在那个 HTTP 响应里回给当前页面；Host 侧不保存调用记录。
- **控制台路由的准入**：MCP 控制台的 `/project-mcp/status` / `start` / `revoke` 与「工具调试」
  Tab 的 `/project-mcp/debug/*` 走**同一套同源三重围栏**——peer 必须是回环地址、`Host` 必须是
  本机 authority、`sec-fetch-site` 只允许 `same-origin`/`none`，带 `Origin` 时还必须与 `Host`
  一致。**桌面版与 Web 版行为一致**，两者都**不依赖往页面注入任何东西**。
  > 这些路由**不用** nonce：nonce 依赖 `tapIndex` 把 meta 注入页面。调试台因此在 2026-10-24
  > 每个请求都被判 403、工具面永远是 0；控制台按钮在 2026-10-28 的桌面版上同理整个不渲染
  > （桌面版页面由 Electron shell 直接读打包产物、不经 Host 渲染，`tapIndex` 在那里永不执行）。
  > 同一套围栏已经挡住了跨站与 DNS rebinding，nonce 不会额外挡住谁。
  > 调试台能执行任意已注册工具，因此只应在本机回环的 GUI 里使用。

## 已知限制

| 限制 | 说明 |
| --- | --- |
| 每会话独立连接 | 项目级服务器在 N 个会话下就是 N 份连接与子进程（profile 里的全局行则只有一份）。stdio 服务器在 `.mcp.json` 给出的 `args` 之后会追加 `--project-mcp-session <会话 id>`，用来分辨进程归属——同一份 `.mcp.json` 在多个会话下的命令行其余部分逐字相同。标记只含会话 id，不含任何配置内容；服务器忽略未知参数，不影响运行 |
| 首条消息可能赶不上工具 | 挂载不等待 MCP 连接，会话秒开的代价是首条消息的当轮可能看不到这些工具，下一轮即可见。**例外**：配了 `serve` 的 HTTP 条目会先等健康检查（有上限、失败不抛），见上文 |
| 不支持的传输 | `sse` / `ws` / `sdk` 一律跳过；SSE 已被 MCP 规范废弃，主流服务器都提供 `streamable-http` |
| 被禁用的全局行仍占名 | 判定全局撞名时只看行的模块名与 `serverName`，不看该行是否 `disabled: true`；后果是禁用行会让同名项目服务器被当作"全局已提供"跳过，而全局侧实际不连接 |
| 全局行不受管辖 | 写在 profile 补丁里的 MCP 行仍会在 DSH 启动时连接；本插件能检测到它们（名单只用于撞名过滤），但**不提示**，也无法阻止。能做的只有改 profile 补丁，那已超出本插件的管辖范围，因此不为一条你无能为力的信息在启动时打扰你 |
| 模块名精确匹配 | 全局行检测要求行的模块名**精确等于** `@deepseek-ai/dsh-mcp-client`；写成子路径或相对路径时漏检 |
| `.mcp.json` 上限 1 MiB | 超过即**拒读**（不读进内存）并给出"过大"诊断。读盘在会话创建的同步路径上，无上限会让陌生仓库里的异常大文件拖住会话创建；真实的 `.mcp.json` 远小于 100 KiB |
| 无 Web UI 的 profile | 本插件只声明依赖 `loader`，因此在 headless / SDK profile 上依然激活；但没有 `webServer` 就没有控制台，也就**没有批准入口**——那里只剩 Host 日志 |
| 挂载只发生在会话创建时或本会话批准时 | 别的会话批准后，本会话的计划已是"已批准"，但服务器不会自动挂进本会话；控制台把它列成 `本会话未挂载` 并计入徽标，点 [启动] 即挂上 |
| `serve` 不管服务生命周期 | 拉起的服务脱离 DSH 存活，插件不 kill、不监控、不重启。好处是多实例复用同一个服务；代价是 `serve` 写错时会留下一个常驻进程，只能手动结束 |
| Windows 上"服务活过 DSH"还取决于怎么拉起 | `serve.command` 是 PowerShell 时插件不用 `detached`（用了它 PowerShell 会一行都不执行）。此时服务能否活过 DSH，取决于启动脚本怎么创建它：`Start-Process -WindowStyle Hidden` 创建的进程没有控制台、能存活；直接跑在脚本前台的会随宿主控制台一起结束。其余命令走 `detached`，能独立存活 |
| `serve` 不检查端口归属 | 端口被别的进程占用时只记一条日志，不抢占、不重试；照常交给 DSH 连接（可能连上那个别的实例） |
| `serve` 的等待有上限 | 默认 120 秒（可配，硬上限 30 分钟）。超时后仍会挂载，工具暂时不可用，由 DSH 自己重连 |
| 调试台不受会话作用域限制 | 它从宿主全局视角列出与执行工具（`schemas()` / `execute()` 都不带 agent scope），因此会话级的工具 deny 补丁**不**作用于它。这是刻意取舍：调试台的价值就是看见真实工具面，而它只能由拿到页面的人手动触发 |
| 调试台的表单不做 schema 校验 | 表单只按 JSON Schema 顶层生成控件，提交前不校验；参数是否合法由工具自己判定（与模型调用同一条路径）。schema 嵌套很深时用「原始 JSON」模式 |

## 卸载

```powershell
dsh plugin --profile web remove deepseek-harness-project-mcp
```

卸载会回收本插件在活会话里挂载的项目级 MCP 与全部控制台注册（路由、监听器），
不会删除 DSH 会话数据。
`${DSH_HOME:-~/.dsh}/project-mcp-trust.json` 会保留——重新安装后此前的批准仍有效。
若要一并清除，请在确认没有其他项目仍需该记录后自行删除该文件。
